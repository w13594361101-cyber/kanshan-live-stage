# 看山有问｜现场互动台

为浦江创新论坛设计的刘看山现场问题接力工具。一位嘉宾回答上一位留下的问题，再把一个新问题交给下一位嘉宾。当前发言安排包含 12 位确认上台的嘉宾，并保留 3 组备用位置。

## 页面入口

- `/`：公开产品首页
- `/?view=stage`：现场大屏，右下角提供自动收起的轻量操作入口
- `/?view=operate`：工作人员现场按钮页（`/?view=control` 保留为兼容入口）
- `/?view=admin`：15 组内容配置后台

## 本地运行

```bash
pnpm install
pnpm dev
```

正式构建：

```bash
pnpm test
pnpm build
```

## 多电脑实时部署

正式部署时由 Node 服务统一保存现场状态，并通过 SSE 将每次操作实时推送给所有已打开的现场大屏。工作人员只操作一个后台，多台电脑、投影设备或浏览器会显示同一轮次和同一结果。

```bash
pnpm install --frozen-lockfile
pnpm run build
CONTROL_TOKEN="请设置现场操作口令" PORT=3000 pnpm start
```

- 公开大屏：`https://活动域名/?view=stage`
- 工作人员按钮页：`https://活动域名/?view=operate&token=现场操作口令`
- 内容配置页：`https://活动域名/?view=admin&token=现场操作口令`
- 健康检查：`https://活动域名/api/health`

操作页出现绿色“服务器实时同步已连接”后才能开始活动。公开大屏没有操作口令时只保留全屏按钮，不能修改现场状态。实时状态保存在 `DATA_DIR/live-state.json`，服务器重启后可以恢复；云服务器应挂载持久化目录。正式活动建议只运行一个服务实例，如需多副本部署则需另外接入共享 Redis 或数据库。

Docker 部署及反向代理说明见 `DEPLOYMENT.md`。`outputs/看山有问-GitHub知乎单文件版.html` 继续作为断网备份，但单文件版仅支持同一电脑内同步，不能代替服务器实时模式。

## 内容配置

前 12 组已根据《0911 下午发言环节安排_0907》录入固定的问题接力顺序，最后一位为孙悦礼；另外 3 组默认关闭。每组包括提问人、中英文问题、回答嘉宾姓名/身份/大屏简介/照片、嘉宾留下的问题和下一位回答嘉宾。上一组留下的问题必须与下一组回答的问题一致。公开大屏不会提前显示下一位姓名，而是播放嘉宾头像与姓名滚动动画后停在预设结果；工作人员后台仍可核对真实顺序。仓库默认值位于 `public/config/activity.json`，12 张优化后的嘉宾照片位于 `public/assets/speakers/`。

问题首次揭晓时采用大卡片；进入抽取嘉宾和嘉宾揭晓阶段后，问题收拢为顶部悬浮卡，仍保持中文主问题清晰可读。英文翻译以较小字号作为中文下方的备注。嘉宾揭晓页中央展示头像、姓名、身份和现场版简介。

嘉宾回答结束后，流程会先进入独立的“请留下一个问题”页面：上一道问题完全消失，画面聚焦当前嘉宾。工作人员点击“展示嘉宾问题”后，新问题才会出现；问题上方同步展示提问嘉宾头像和姓名。随后再进入下一位回答嘉宾的头像滚动抽取页面，公开大屏不会提前泄露下一位姓名。

刘看山会在问题揭晓、嘉宾抽取、回答、留题和结束等关键页面显示引导气泡。气泡文案跟随人工切换后的页面状态，并持续展示到下一步，不依赖现场发言的实时结束时间；同类文案按轮次固定切换，保证有变化且便于彩排。嘉宾姓名只会在抽取结果揭晓后出现在气泡中。

舞台视觉会随问题揭晓、嘉宾抽取、嘉宾登场、留题和结束切换不同动效。嘉宾抽取采用先快后慢的固定结果停靠；提问嘉宾与问题卡之间使用黄色接力线；结束页会展示所有启用嘉宾的头像、嘉宾人数和问题传递次数，形成稳定的现场合影画面。

## 现场建议

1. 所有设备通过同一个服务器地址打开页面；操作端确认显示绿色“服务器实时同步已连接”。
2. 将舞台页全屏输出至 LED 大屏；页面采用固定 16:9 舞台画布，兼容 1920×1080、1366×768 和 4K 等同比例分辨率。
3. 活动前关闭系统通知并按实际启用组完整彩排。
4. 保留单文件版作为断网备份，但正式流程以服务器状态为准。

现场大屏可按空格键推进流程，按 `F` 进入或退出全屏。右下角操作入口在无操作 3 秒后降低存在感，避免影响现场拍照。
